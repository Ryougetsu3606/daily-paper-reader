## 摘要
视觉-语言-动作（VLA）或世界动作（WAM）模型近来在机器人操作中展现出卓越性能。在 LIBERO 上，SOTA 方法已取得接近 100% 的成功率，似乎表明这些模型已准备好在真实世界中部署。然而，在现有基准上近乎完美的表现可能具有误导性：理想条件下的成功并不意味着真实世界中的鲁棒性。现有基准主要评估从预定义初始状态开始的任务完成情况，而真实世界交互不可避免地涉及失败，例如抓取失败、碰撞和意外物体移动。因此，机器人不仅需要成功执行任务，还必须识别失败并从中恢复，以继续任务。然而，这一能力在很大程度上仍未被衡量，揭示了基准性能与真实世界可靠性之间的关键差距。为弥补这一差距，我们提出了 LIBERO-Recover Benchmark，一个面向机器人操作中失败恢复的大规模基准。基于 LIBERO，我们收集了来自 SOTA 具身模型的真实执行失败，并构建了跨越四个恢复级别的 1,000+ 个场景：（1）动作重试，（2）动作适应，（3）物体状态恢复，（4）环境恢复。我们评估四项核心能力：空间理解、物体结构推理、交互理解和拓扑推理。作为首个面向具身失败恢复的大规模基准，LIBERO-Recover 将评估从“机器人能否成功？”转向“机器人能否在失败后恢复？”，推动稳健且可泛化的具身智能体发展。项目将发布于 https://liulin815.github.io/LIBERO-Recovery/。

## Abstract
Vision-Language-Action (VLA) or World Action (WAM) models have recently demonstrated remarkable performance in robotic manipulation. On LIBERO, SOTA method have achieved nearly 100\% success rates, seemingly suggesting that the models are ready for deployment in real world. However, near perfect performance on existing benchmarks can be misleading: success under ideal conditions does not imply real world robustness. Existing benchmarks primarily evaluate task completion from predefined initial states, while real world interactions inevitably involve failures such as failed grasps, collisions, and unintended object movements. A robot must therefore not only execute tasks successfully, but also recognize and recover from failures to continue the task. Yet this capability remains largely unmeasured, revealing a critical gap between benchmark performance and real world reliability. To address this gap, we introduce LIBERO-Recover Benchmark, a large scale benchmark for failure recovery in robotic manipulation. Built upon LIBERO, we collect real execution failures from SOTA embodied models and construct 1,000+ scenarios across four recovery levels: (1) Action Retry, (2) Action Adaptation, (3) Object State Recovery, and (4) Environmental Recovery. We evaluate four core capabilities: spatial understanding, object structure reasoning, interaction understanding, and topological reasoning. As the first large-scale benchmark for embodied failure recovery, LIBERO-Recover shifts evaluation from \emph{Can the robot succeed?''} to \emph{Can the robot recover after failure?''}, promoting robust and generalizable embodied agents. The project will be avaible in \textcolor{blue}{https://liulin815.github.io/LIBERO-Recovery/}.

## 2. 方法论

- **核心思想**：不通过人工扰动初始状态来合成失败，而是从 SOTA 具身模型的真实执行轨迹中采集自然发生的失败，并据此构建分级恢复场景。
- **问题形式化**：
  - 任务由语言指令 \(l\) 和目标条件 \(G\) 指定，策略从初始状态 \(s_0\) 生成轨迹 \(\tau=(s_0,a_0,s_1,\dots,s_T)\)。
  - 失败状态 \(s_f\) 满足 \(G(s_f,l)=0\)，但任务仍可恢复，即存在恢复策略 \(\pi_{rec}\) 使最终 \(G(s_T,l)=1\)。
  - 失败定义强调三点：由执行动作诱发、任务相关、使原计划失效。
- **四级恢复难度分类**：
  - **L1 Action Retry**：失败未实质改变任务配置，只需重试失败动作。
  - **L2 Action Adaptation**：物体配置发生有限变化，需根据当前观察调整动作，而非盲目重复。
  - **L3 Object State Recovery**：任务相关物体状态显著改变，需先恢复物体状态再继续原任务。
  - **L4 Environmental Recovery**：非直接操作对象或环境状态阻碍任务执行，需识别并恢复环境配置后再继续。
- **场景构建流程**：
  - **Stage 1 任务执行**：基于 LIBERO 四个任务套件、130 个子任务，使用 π0、π0.5、OpenVLA、GR00T、Wan-Policy、Cosmos-Policy 等作为失败生成器，不手动扰动场景、不注入失败。
  - **Stage 2 失败定位**：用 Qwen3.5-27B-Instruct 分析执行视频，定位失败前、失败中、失败后阶段，并从模拟器提取对应状态和物体位姿。
  - **Stage 3 失败表征**：用同一模型判断失败后果，并按四级分类标注恢复类型与难度。
- **恢复数据采集**：四名人类遥操作者使用 SpaceMouse 收集 **3,184 条恢复轨迹**，覆盖 **413 个失败场景**，用于模型微调。
- **评估指标**：
  - **RSR / Recovery Success Rate**：进入失败状态后能否最终完成任务，并分 L1–L4 报告。
  - **RD / Recovery Degradation**：衡量失败后执行能力相对失败前的下降程度，越低越好。
  - **RC / Recovery Consistency**：衡量同一任务在不同失败场景下恢复成功率的一致性，越高越好。

## 6. 主要结论与发现

- **标准成功不等于失败恢复能力**：所有模型在真实失败场景下性能大幅下降，多个模型下降超过 50%；标准 LIBERO 排名不能可靠预测失败恢复表现。
- **动作级校正强于状态级恢复**：模型在 L1/L2 上明显优于 L3/L4，说明当前模型能局部调整动作，但难以推理并恢复被破坏的任务状态。
- **失败会引发复合分布偏移**：失败后性能进一步下降，表明重复失败交互可能把执行推入越来越陌生的状态，失败不是短暂扰动。
- **WAM 策略恢复一致性更高**：Wan2-Policy 和 Cosmos-Predict2-Policy 的 RC 高于传统 VLA，可能因为世界模型显式建模动作条件状态转移，具有更强的状态转移归纳偏置。
- **更小动作块有利于恢复**：动作块从 4 增大到 32 时恢复成功率下降，说明更频繁的闭环反馈有助于纠正失败后的偏差。
- **恢复训练迁移有限**：混合 LIBERO-Recover 数据能提升恢复任务表现，但对标准 LIBERO 任务提升很小，甚至略有下降，存在“失败恢复迁移鸿沟”。
- **时间上下文有帮助**：提供任务初始帧作为时间上下文可提升恢复表现，尤其对较难设置提升明显，说明恢复需要比较当前状态与预期状态。
- **恢复状态分布更集中**：LIBERO-Recover 的失败恢复轨迹集中在抓取、放置、物体交互等关键状态区域，而标准 LIBERO 数据覆盖更分散的成功执行状态。
